# lines

## Purpose

- The websites of Luan Fabri's "lines" (apps that need only a code or a link, no company server), one Next.js app serving each line at its own subdomain of luannzin.com: `deskline.luannzin.com` and `hostline.luannzin.com` today, `partyline.luannzin.com` next
- `hostline.luannzin.com` is also the browser half of Hostline itself: every shared link opens there (`src/app/hostline/AGENTS.md`)
- `PRODUCT.md` is the product brief (audience, facts on hand, what never gets invented); `DESIGN.md` is the binding design system; every user-facing string follows Luan's voice: `luannzin.com/IDENTITY.md`, `luannzin-online-presence/VOICE.md` and the `luan-writing-way` skill in `luannzin.com/.claude/skills/`
- Not here: the apps' code and releases (each line's own repo); Sightline (its subdomain is the Sightline app itself, its own Vercel project); LanPet (no page yet)

## Ownership

Root owns repo-wide config and the folders without their own AGENTS.md:

- `package.json`, `bun.lock`: Bun; scripts `dev`, `build`, `start`, `lint` (`biome check`), `test` (`bun test`), `format`
- `next.config.ts`: `reactCompiler`, security headers (on `hostline.*` the Permissions-Policy allows camera, microphone and location for the shared app's frame), Tailwind v4 Turbopack loader, better-intl wrapper
- `intl.config.ts`: better-intl locales `en` and `pt`, `onMissing: "error"`; generates `src/i18n/generated.ts` from every `t.ts` under `src/` (gitignored, regenerated by `next dev` and `next build`)
- `src/proxy.ts`: maps the request's host to its line (`deskline.*` serves `/deskline`); paths with a dot, `/_next/` and `/_vercel/` pass through, so `/deskline/mark.png` works on every host. On `hostline.*` every path, dots included, serves `/hostline` (the path is the shared app's), except `/_next/`, `/_vercel/`, `/hostline-sw.js` and `/__hostline/`
- `src/components/analytics.tsx`: Vercel Web Analytics in the root layout, page views only
- `public/hostline-sw.js`, `public/__hostline/inject.js`: Hostline's service worker and the script it puts in every shared page; plain JavaScript, owned by `src/app/hostline/AGENTS.md`
- `src/lib/lines.ts`: the lines with a page, and each one's origin; `src/lib/dusk.ts`: the shared palette, Bayer matrix and dot grid; `src/lib/locale.ts`: the Server Action that switches language
- `src/components/line/`: the shared landing template (`line.tsx`: the night field hero with the download for the visitor's system, the live piece, the line's sections, every file, the footer), `night-field.tsx` (its `band` and `under` props let a field fill a whole screen with nothing below it, as Hostline's shell does; the hero uses the defaults), `pixel-name.tsx` (the 5x7 face from the apps' `tools/logo.py`), `t.ts`
- `src/components/ui/`: the coss UI parts in use (button, spinner, input, checkbox), added with `bunx --bun shadcn@latest add @coss/<name>`; add a part only when a page uses it
- `src/app/<line>/`: one folder per line: `page.tsx` (its words, files and sections through `Line`), `t.ts`, `layout.tsx` (its `metadataBase`), `icon.png` and `opengraph-image.png` (copied from the line's repo, drawn by its `tools/logo.py`), and its live piece
- `public/<line>/`: art the pages load by path (`mark.png`, the 32x32 mark; Hostline adds `mark-out.png` and the turning strips `mark-spin.png` and `mark-spin-lit.png`)
- `.impeccable/`: impeccable skill state (surface briefs with the direction contract, `design.json`)
- `tools/social.py` (`python tools/social.py`, Pillow): draws Luan's social images in the README banners' world into `assets/social/`: `linkedin-banner.png` (1584x396: "The Lines" and its lead on the night at left, inside the centre 70% and above where LinkedIn's round photo lands; Deskline's, Sightline's and Hostline's marks at 5x, each on its own glow) and one 1200x1200 card per project (`deskline`, `sightline`, `hostline`, `lanpet`: the mark at 12x, centred on its glow, no words, since LinkedIn prints the name beside its media). Words never sit on a cut-out plate of night, and the soft ink only crosses violet dots (5.75:1; plum is 4.0:1). `tools/marks/` holds the 32x32 marks it can't take from `public/` (Sightline's, LanPet's frog). These are files he uploads by hand; nothing serves them

## Local Contracts

- Every user-facing string lives in a `t.ts` with `en` and `pt`; the namespace follows the folder (`src/app/deskline/t.ts` is `t.app.deskline`)
- The language comes from the `locale` cookie, else Accept-Language; the download from the request's client hints and user agent; so pages render per request
- Facts come only from each line's README and PRODUCT.md. No users, numbers, testimonials or reasons get invented; ask Luan one specific question when a reason is missing
- Downloads are `https://github.com/luannzin/<repo>/releases/latest/download/<file>` with the README's file names, checked against the latest release's assets. Nothing reads GitHub at build or request time (his decision); a renamed file is changed here by hand
- Colour only inside the art (night field, marks, the link); the interface stays on the neutral ink tiers
- Analytics count page views and nothing else: no custom events, every address cut at its `#`, and a Hostline link's page (`html[data-link]`) never counted, since its path belongs to the shared app
- A new line: add it to `lines`, give it `src/app/<line>/` and `public/<line>/`, a subdomain in Vercel (Luan adds it), and its live piece

## Verification

- `bun run build`: type check and i18n completeness (a missing `pt` string fails)
- `bun test`: the demo's code format and link-quality measure, Hostline's links and room (the room must match the CLI's)
- Previewable changes: `next dev`, then `http://deskline.localhost:<port>/` (the proxy routes by host) at phone and desktop widths, in both languages, by keyboard and under reduced motion; for Deskline, run the demo through Accept and check the video and the pointer
